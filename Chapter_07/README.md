1. Introduction to Advanced Text Generation

In the previous chapter, we learned how prompt engineering improves the responses generated by Large Language Models (LLMs). However, prompt engineering alone is not enough for building powerful AI applications. Chapter 7 introduces advanced techniques that enhance an LLM without changing or fine-tuning the model itself. These techniques include Model I/O, Chains, Memory, and Agents. Together, they make LLMs capable of solving more complex tasks, remembering previous conversations, and interacting with external tools. Most modern AI applications use these techniques to build intelligent and reliable systems.

2. LangChain Framework

LangChain is an open-source framework that helps developers build applications using LLMs such as GPT, Llama, and Phi-3. It is not a language model, but a framework that connects different components like prompt templates, memory, chains, agents, and external tools with an LLM. LangChain simplifies the process of creating AI applications by providing reusable building blocks. Instead of writing everything from scratch, developers can connect these components together to create powerful LLM-based systems. It acts as a bridge between the user and the language model.

3. Model I/O and Quantized Models

Before using LangChain, we first need to load an LLM. The chapter introduces GGUF models, which are compressed versions of normal LLMs created using quantization. Quantization reduces the number of bits used to store model parameters, such as converting a 16-bit model into an 8-bit or 4-bit model. This greatly reduces memory usage and makes the model run faster while maintaining nearly the same accuracy. The model is loaded using LlamaCpp, and LangChain communicates with it using the invoke() method. This allows us to generate responses efficiently on computers with limited hardware.

4. Chains

A Chain is one of the most important concepts in LangChain. A chain connects an LLM with one or more additional components, such as a prompt template, memory, or another chain. Instead of sending a question directly to the LLM, the input passes through these connected components before reaching the model. Chains make applications more organized, reusable, and modular. They also allow developers to combine multiple processing steps into a single workflow. This makes it easier to build complex AI systems without rewriting code repeatedly.

5. Prompt Templates (Single Chain)

A Prompt Template is a reusable prompt containing fixed text and variables. Instead of writing the same prompt every time, developers define it once and replace only the variable values. For example, Phi-3 requires a special prompt format containing tokens such as <|user|> and <|assistant|>. Using LangChain, the prompt template automatically inserts the user's input into the correct format before sending it to the LLM. This reduces repetitive work, improves consistency, and ensures that the model always receives properly formatted prompts.

6. Multiple Chains (Sequential Chains)

Sometimes a single prompt is too complicated for an LLM to handle efficiently. Instead, LangChain allows us to divide a complex task into several smaller chains called Sequential Chains. In the chapter, the example generates a story by first creating a title, then describing the main character, and finally writing the story itself. Each chain receives the output from the previous chain as its input. Breaking a large task into smaller subtasks improves the quality of the output and makes each step easier to understand and manage.

7. Memory in LangChain

By default, an LLM does not remember previous conversations. Every new prompt is treated as an independent request. LangChain solves this limitation using Memory, which stores previous conversations and automatically includes them in future prompts. This allows the LLM to answer follow-up questions naturally, just like a human conversation. Memory is essential for chatbots, virtual assistants, and customer support systems because it enables context-aware conversations. Without memory, the model would forget everything after each response.

8. ConversationBufferMemory

ConversationBufferMemory stores the entire conversation history between the user and the AI. Every question and every answer are saved and sent back to the LLM whenever a new question is asked. This allows the model to remember all previous discussions and maintain long conversations. However, because every message is stored, the number of tokens keeps increasing, making responses slower and more expensive. It is best suited for short conversations where remembering every detail is important.

9. ConversationBufferWindowMemory

ConversationBufferWindowMemory improves memory efficiency by storing only the most recent k conversations instead of the complete history. For example, if k = 2, only the last two conversations are remembered, while older conversations are automatically removed. This reduces token usage and keeps the conversation fast even during long chats. Although it forgets older information, it is very useful when only recent context matters. It provides a good balance between memory usage and conversational quality.

10. ConversationSummaryMemory

ConversationSummaryMemory stores a summary of previous conversations instead of storing every individual message. After each new interaction, the LLM summarizes the conversation and updates the summary with the latest information. This approach greatly reduces the number of tokens while still preserving the important context of the conversation. It is ideal for very long chats because the summary remains short and efficient. However, small details may sometimes be lost during summarization.

11. Agents

An Agent is a more advanced system built on top of an LLM. Unlike chains, which follow a fixed sequence of steps defined by the programmer, an Agent can think, make decisions, and choose which tool to use based on the user's request. Agents combine prompt templates, memory, chains, and external tools into one intelligent system. They are capable of solving more complex tasks by deciding the best sequence of actions without human intervention. This makes Agents much more flexible and powerful than ordinary LLM applications.

12. Tools in Agents

Tools are external resources that extend the capabilities of an LLM. Examples include calculators, search engines, weather APIs, databases, and Python interpreters. Since LLMs can only generate text, they cannot directly perform these actions by themselves. Agents use tools whenever they require information or computations beyond their internal knowledge. By connecting multiple tools, an Agent becomes capable of solving a wide variety of real-world problems accurately and efficiently.

13. ReAct (Reasoning and Acting)

The chapter introduces the ReAct framework, which stands for Reasoning and Acting. ReAct enables an Agent to first think about a problem, then use an appropriate tool, observe the result, and repeat the process if necessary. Each cycle consists of Thought, Action, and Observation. This reasoning process allows the Agent to break complex tasks into multiple logical steps. Instead of guessing answers, the Agent gathers information using tools before generating its final response, making the results more accurate and reliable.

14. ReAct Prompt Template

To use ReAct, LangChain requires a special prompt template that instructs the LLM to follow the Thought → Action → Observation cycle. The prompt also lists all available tools, the names of those tools, the user's input, and the agent's scratchpad for storing intermediate reasoning. During execution, the LLM repeatedly generates thoughts, chooses actions, observes the results, and continues until it reaches the final answer. This prompt template serves as the instruction manual that guides the Agent's behavior.

15. Building a ReAct Agent in LangChain

The chapter demonstrates how to build a complete ReAct Agent using LangChain. GPT-3.5 is used as the language model because it follows complex instructions better than smaller local models. The Agent is provided with two tools: DuckDuckGo Search for finding current information on the internet and LLM-Math for performing calculations. When the user asks for the current price of a MacBook Pro in USD and its value in EUR, the Agent first searches the web for the latest price, then uses the calculator to convert the currency, and finally provides the correct answer.

16. Advantages and Limitations of Agents

Agents are extremely powerful because they can reason, choose tools, and solve multi-step problems automatically. They can perform tasks that normal LLMs cannot, such as searching the internet or performing accurate calculations. However, Agents also have limitations because they rely on the quality of the tools and the reasoning process. If a tool returns incorrect information or the Agent makes a poor decision, the final answer may also be incorrect. Therefore, well-designed prompts, reliable tools, and proper system design are necessary to improve their reliability
